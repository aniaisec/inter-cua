# Evidence

Every folder here is one run directory, exactly as the system wrote it: a
JSONL event log, masked screenshots, the scrubbed accessibility tree behind
each step (`observations/`), and `result.json`. The two discovery folders are
real model runs, copied as they were written. Every replay folder is
regenerated by one command against a fresh mock app:

```
make evidence          # or: python -m cua.evidence.build
```

The build starts the mock app on the tenant's port (`:8000`, so that must be
free) and the operator console. It then makes every call through the `cua`
CLI and keeps what each call printed (`cli-*.json`) next to the command line
that made it (`commands.txt`). Nothing is replaced unless every scenario
returns what it should. A redaction scan of this whole folder runs last and
fails the build on a hit. `python -m cua.evidence.build --scan` runs the scan
alone. `runs/` is the local working directory and is not committed.

## What each folder proves

| Folder | What it shows | Look at |
|---|---|---|
| `discovery-member-savings-balance/` | Goal 1 discovered by a real model (Gemini) from the goal alone: sign on, search, read the balance | `log.jsonl` (the model's reasoning per turn), `model_calls.jsonl` (response ids, tokens, the model that answered) |
| `discovery-open-subaccount/` | Goal 2 discovered by a real model. At Confirm, policy stops the agent (`NEEDS_APPROVAL`) and a person approves on the operator console | `interventions/`, `state_transitions.jsonl`, `human_actions.jsonl`, `log.jsonl` (`policy.approved via console`) |
| `capability-*.json` | The two capabilities those runs recorded, as approved and replayed below | `provenance.discovery_run_id` names the folder's run |
| `replay-success/` | Goal 1 replayed with no model: the balance, the locator rung each step used | `result.json`: `outputs`, `locator_rungs_used` |
| `replay-not-found/` | An unknown member is a business outcome, not a failure (exit 2) | `result.json`: `NOT_FOUND` at `search.submit` |
| `replay-server-error/` | HTTP 500 on the member page: a failure that says where, what was expected, what was seen | `result.json`: `APP_ERROR`, `expected`/`observed`; `trace.zip` (open with `playwright show-trace`) |
| `replay-slow-confirm/` | Confirm pressed once and not answered in time: `side_effect: unknown`, never pressed again | `result.json`: `TIMEOUT`, `side_effect`; `log.jsonl`: one `irreversible.act` |
| `replay-needs-approval/` | Goal 2 without an approval token: the commit waits for a person, who approves on the console; it commits once | `result.json` `handoffs[0]`, `state_transitions.jsonl` |
| `replay-escalation/` | A notice the capability never saw blocks the member page. A person takes the live session over CDP and closes it. The run checks the screen and carries on from `cp.member_detail` | `interventions/*.json` (reason, step, masked screenshot, CDP url), `human_actions.jsonl` (the click), `state_transitions.jsonl` (who held the controls) |
| `replay-resume-after-human/` | The run returns `escalated` (exit 3) and its process ends. A person finishes the lookup in the still-open browser, and `cua resume` finds the screen already at `cp.done`, so no step runs again | `cli-replay.json` then `cli-resume.json`; `result.json` `handoffs[0].resumed_after_checkpoint` |

## Honest notes

- **The person in the replay handoffs is a script.** It signs itself
  `evidence-bot` and lives in `cua.evidence.build`. It uses the same doors a
  person would: it polls the console's API, takes control, drives the live
  page over the request's CDP endpoint with its own Playwright connection, and
  decides. In the goal-2 discovery run a person approved by hand.
- **Human actions carry no typed values.** A typed value is recorded as which
  control and how many characters.
- **Removed from the copies:** the live-session plumbing (`session.json`,
  `waiter.json`: a pid, a port, a temp profile path). The temp profile path is
  also blanked inside `handoff_state.json`.
- **Screen contents reach the model during discovery.** Mitigations: all data
  is synthetic (members 10001-10010, "Test Member NN"), credential fields are
  masked in screenshots, and credential values are scrubbed from the trees
  and logs.
