# Evidence

Every folder here is one run directory, exactly as the system wrote it: a
JSONL event log, masked screenshots, the scrubbed accessibility tree behind
each step (`observations/`), and `result.json`. The two discovery folders are
real model runs, copied as they were written. Every replay folder
except the desktop and vision ones is regenerated by one command against a
fresh mock app:

```
make evidence          # or: python -m cua.evidence.build
```

The build starts the mock app on the tenant's port (`:8000`, so that must be
free) and the operator console. It then makes every call through the `cua`
CLI and keeps what each call printed (`cli-*.json`) next to the command line
that made it (`commands.txt`). Nothing is replaced unless every scenario
returns what it should. A redaction scan of this whole folder runs last and
fails the build on a hit. `python -m cua.evidence.build --scan` runs the scan
alone. `runs/` is the local working directory and is not committed.

## Honest notes

- The four `replay-vision-*` folders are the runs made by hand while Phase 9
  was verified, against the mock app on `:8000`. The capability each ran is
  recorded from the committed discovery run at schema 1.3 and approved by the
  person verifying; it is kept beside the run as `capability.json`. The
  committed v3 capabilities carry no recorded picture. One field was changed:
  `result.json`'s `run_dir`, from the temp directory the run was made in to
  its folder here.

- **The person in the replay handoffs is a script.** It signs itself
  `evidence-bot` and lives in `cua.evidence.build`. It uses the same doors a
  person would: it polls the console's API, takes control, drives the live
  page over the request's CDP endpoint with its own Playwright connection, and
  decides. In the goal-2 discovery run a person approved by hand.
- **Human actions carry no typed values.** A typed value is recorded as which
  control and how many characters.
- **Removed from the copies:** the live-session plumbing (`session.json`,
  `waiter.json`: a pid, a port, a temp profile path). The temp profile path is
  also blanked inside `handoff_state.json`.
- **Screen contents reach the model during discovery.** Mitigations: all data
  is synthetic (members 10001-10010, "Test Member NN"), credential fields are
  masked in screenshots, and credential values are scrubbed from the trees
  and logs.
